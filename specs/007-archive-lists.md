# Списки митапов, докладов и спикеров

## Зачем

В архиве 32 митапа, 106 докладов и 85 спикеров, но попасть к ним можно только с главной (список
прошлых митапов) или через поиск Pagefind. Человек, который помнит «был доклад про контейнерные
запросы» или «выступал кто-то из Яндекса два года назад», не может пролистать доклады или спикеров
целиком. Агент тоже видит только поиск по словам и не может попросить «доклады 2023 года с видео».

## Что делаем

- **Три страницы на каждом языке:** `/events/`, `/talks/`, `/speakers/` (и `/en/…`). На каждой
  шапка сайта, заголовок `h1`, строка-переключатель между тремя списками, фильтры и сам список.
  У списка прошлых митапов на главной появляется ссылка на все списки.
- **Шапка — навигация по сайту, а не по главной** (решение владельца): якоря «Регистрация»,
  «Программа», «Партнёры», «Адрес» уходят (регистрацию ведёт плавающая кнопка, остальное —
  экраны главной под первым). В шапке: «История» → `/events/`, «Доклады» → `/talks/`,
  «Спикеры» → `/speakers/`, «О митапе» → `/about/` (страница уже есть со спеки 003), «Поиск».
- **Митапы** — от последнего к первому: название, дата, площадка, число докладов, метки «запись»
  и «фото», если ссылки есть. Будущий митап стоит первым.
- **Доклады** — от последнего митапа к первому, внутри митапа — по порядку программы: название,
  спикеры, метка митапа, метки «видео» и «слайды».
- **Спикеры** — карточки сеткой по образцу таблицы из макета (рамка `border.width.thin` цвета
  `color.border`, соседние рамки схлопываются в одну линию, внутренние поля постоянные). В
  карточке фото (или аватар с инициалами), имя и фамилия, до трёх меток последних митапов спикера.
  На телефоне один столбец, дальше столбцов больше. Порядок — по самому свежему выступлению:
  выступил на 31-м и на 10-м — стоит среди спикеров 31-го; спикер один раз, без повторов. Спикеры
  одного митапа — в порядке программы. Спикеры без опубликованных докладов — в конце по имени.
- **Метка митапа** — номер из имени файла (`22`, `28`); у митапа с нечисловым именем
  (`online-2021`, `19-plus`) — год.
- **Фильтры на странице, без перезагрузки:** текстовое поле (ищет по названию, имени, площадке,
  без учёта регистра и `ё`/`е`), у докладов и митапов — год, у докладов — «есть видео», у
  митапов — «есть запись». Состояние фильтра пишется в адрес (`?q=…&year=…`), ссылку можно
  отправить. Счётчик «показано N из M» объявляется скринридеру через `aria-live`. Ничего не
  нашлось — сообщение и кнопка «сбросить».
- **Без JavaScript** виден полный список, фильтры скрыты: список — обычная разметка, скрипт только
  прячет лишнее.
- **Агентам:** у каждой страницы списка Markdown-версия `index.md` с полным списком и ссылками;
  списки есть в `llms.txt`. WebMCP получает инструмент `list_archive` (вид: митапы, доклады,
  спикеры; фильтры: текст, год, только с видео/записью; лимит) — тот же фильтр, что на странице,
  по JSON-данным, собранным на сборке (`/archive.json`, `/en/archive.json`).

## Планка качества

- **Фильтр — одна чистая функция** для страницы и для WebMCP, с тестами на границы (пустой
  запрос, `ё`, год без митапов, сочетание фильтров). Две реализации разойдутся с первой правки.
- **Порядок — тоже чистые функции каталога с тестами**, а не сортировка в `.astro`: правило
  «последнее выступление поднимает спикера» проверяется на фикстурах с повторным спикером.
- **Внешний вид — из токенов, в рамках текущего дизайна.** Новые компоненты (карточка спикера,
  сетка, строка фильтров) — в `@moscowcss/ui`, со сторис, JSDoc у пропсов, зона нажатия не меньше
  `size.hitTarget`, контраст и фокус по правилам спеки 006. Сырых `px`, hex и брейкпоинтов нет.
- **Страницы — полноценные публичные:** canonical, hreflang, OG/Twitter-карточка, JSON-LD
  `CollectionPage` + `ItemList`, sitemap, `check:seo` их проверяет.
- `archive.json` — данные, которые и так видны на страницах; новых полей и персональных данных
  в нём нет.
- Секции главной не меняются, кроме ссылки на списки под прошлыми митапами.

## Вне охвата

- **Серверный поиск и API.** Сайт статический на GitHub Pages; `archive.json` — файл сборки, а
  не API, и в ARD как API не описывается.
- **Пагинация.** 106 докладов — одна страница; фильтр работает по всему списку.
- **Фильтр по тегам тем докладов.** У докладов нет тем в контенте; добавлять поле — отдельная
  работа с редакторами.
- **Редизайн существующих страниц** митапа, доклада, спикера.

## Критерии приёмки

- **AC-1.** В `dist` есть `events/`, `talks/`, `speakers/` и их `en/`-версии; у каждой `index.html`
  и `index.md`; `check:seo` проходит и проверяет их.
- **AC-2.** Порядок митапов и докладов — от новых к старым (доклады внутри митапа — по
  программе); порядок спикеров — по самому свежему выступлению, без повторов, спикеры без
  докладов в конце. Проверка — тесты на фикстурах с повторным спикером.
- **AC-3.** Карточка спикера ведёт на его страницу, показывает фото или аватар, имя и не больше
  трёх меток последних митапов (`31`, `28`, `22`; `online-2021` → `2021`). Сетка: один столбец до
  `tablet`, больше столбцов шире; соседние рамки — одна линия толщиной `border.width.thin`.
- **AC-4.** Фильтры: текст (регистр и `ё` не важны), год, «есть видео»/«есть запись»; состояние в
  адресе и восстанавливается из него при загрузке; счётчик в `aria-live`; пустой результат —
  сообщение и сброс. Тесты чистой функции фильтра и разбора адреса.
- **AC-5.** Без JavaScript страница показывает полный список и не показывает фильтры.
- **AC-6.** Ссылки шапки на обоих языках — ровно «История» (`/events/`), «Доклады» (`/talks/`),
  «Спикеры» (`/speakers/`), «О митапе» (`/about/`), «Поиск» (`/search/`), у текущего раздела
  `aria-current="page"`; якорей главной в шапке нет; под прошлыми митапами на главной есть ссылки
  на три списка; страницы списков связаны строкой-переключателем с
  `aria-current="page"` у текущей.
- **AC-7.** WebMCP регистрирует `list_archive` с `inputSchema`; инструмент читает
  `archive.json` своего языка и фильтрует той же функцией; тесты на фейковом окружении.
  `llms.txt` ссылается на Markdown-версии трёх списков.
- **AC-8.** `pnpm lint`, `pnpm test`, `pnpm build`, `check:seo`, `build:storybook`, `check:a11y`
  зелёные; `tools/visual` показывает, что секции главной, кроме блока прошлых митапов, не
  сдвинулись.

## Решения

| Дата | Что | Решение | Почему | Цена ошибки |
|---|---|---|---|---|
| 2026-11-05 | метка митапа | Номер из имени файла, у нечисловых — год | Поле `label` в схему не добавляем: таких митапов два, и год их отличает | Две метки «2021»/«2023» читаются как годы, а не номера |
| 2026-11-05 | шапка | Пять ссылок по сайту вместо якорей главной (решение владельца) | Регистрацию ведёт плавающая кнопка, программа, партнёры и адрес — экраны главной | С внутренней страницы до адреса площадки — через главную |
| 2026-11-05 | спикеры | Сетка карточек по рамкам таблицы из макета, не таблица | Таблица из 85 строк с фото на телефоне не читается; макет дал рамку и поля | Нет сортировки по столбцам |
| 2026-11-05 | данные для агента | `archive.json` на сборке, фильтр в браузере | На Pages нет сервера; инструменту нужны поля (год, видео), которых нет в поиске Pagefind | Файл ~60 КБ грузится только при вызове инструмента |
