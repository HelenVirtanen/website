# Архитектура сайта по образцу блога

## Зачем

Сайт MoscowCSS сейчас — одна русская страница текущего митапа. Тексты, расписание и данные
партнёра зашиты в TS-модули и разметку секций (`apps/website/src/data/*.ts`, `FAQSection.astro`).
Отсюда четыре проблемы:

1. **Нет второго языка.** Англоязычному участнику показать нечего, а строки интерфейса
   захардкожены в секциях — перевод без переделки некуда положить.
2. **Нет истории.** Митап 31 прошёл (9 июля 2026), а на сайте нет ни прошлых митапов, ни
   страниц докладов и спикеров. Спикер, выступавший на 10-м и 15-м митапах, нигде не связан со
   своими докладами. Заполнить данные может только разработчик, правя TS; с телефона это сделать
   нельзя.
3. **Ссылка на сайт в Telegram и X выглядит пусто.** OpenGraph- и Twitter-разметки нет совсем,
   нет даже `description`.
4. **Адаптив размазан.** Размеры на брейкпоинтах задаются в шести компонентах и пяти секциях
   своими `@media`, ступени шкалы отступов растут на desktop и молча меняют поля всех
   компонентов сразу, значения записаны в `px`. Выше 1920px интерфейс не масштабируется.

В блоге (`/home/r/common/0work/blog`) эти задачи уже решены, и решения проверены продом. Сайт
переходит на ту же архитектуру, сохраняя свои значения токенов и внешний вид.

## Что делаем

**Языки.** Русский — язык по умолчанию, без префикса в адресе; английский — под `/en/`. У каждой
страницы есть переключатель языка, ведущий на ту же страницу другого языка (если перевода нет —
на главную языка), и `hreflang`-ссылки на обе версии плюс `x-default`. Все строки интерфейса
берутся из словаря языка или из контента, в разметке секций текста нет. Английская версия
заполнена переводом текущего русского контента.

**Контент — отдельный пакет.** Весь контент лежит в пакете `@moscowcss/content` файлами `.md`
(frontmatter + Markdown-тело), по папке на язык: `<коллекция>/<язык>/<имя>.md`. Перевод — файл с
тем же путём в папке другого языка. Коллекции: страницы сайта (главная с текстом «о митапе»),
митапы, доклады, спикеры, партнёры, вопросы FAQ. Связи хранятся в одном месте — в докладе: он
называет свой митап и своих спикеров по имени файла. Расписание митапа, страница спикера со всеми
его докладами разных лет, список докладов митапа — собираются на сборке обратным поиском, руками
не дублируются. Перерывы и активности без спикера описываются в расписании митапа.

Сборка проверяет контент и падает с понятной ошибкой, называющей файл и поле: обязательное поле
не заполнено, ссылка ведёт на несуществующий митап или спикера, у перевода разошлись поля,
которые от языка не зависят (дата, время, митап, спикеры, ссылки).

Новую запись создаёт команда (`pnpm new:event`, `new:talk`, `new:speaker`, `new:partner`,
`new:faq`): заготовки на обоих языках из шаблонов пакета, существующие файлы не трогаются. README
пакета объясняет, как завести митап, доклад и спикера и как править файлы с телефона через
веб-редактор GitHub.

**Страницы.**
- Главная — текст «о митапе», ближайший митап (дата, место, регистрация, трансляция, расписание,
  партнёр, FAQ — нынешние секции) и список прошлых митапов со ссылками. Если будущего митапа нет,
  главная показывает последний прошедший в состоянии «прошёл»: без кнопки регистрации, со ссылкой
  на запись, если она есть.
- Страница митапа `/events/<номер>/` — описание, дата, место, расписание с докладами и перерывами.
- Страница доклада `/talks/<имя>/` — название, описание, митап, спикеры, ссылки на запись и слайды.
- Страница спикера `/speakers/<имя>/` — фото, роль, о себе и все его доклады по всем митапам.
- Поиск `/search/` на Pagefind по страницам митапов, докладов и спикеров своего языка.

Новые страницы собираются из компонентов `@moscowcss/ui` и токенов; макетов у них нет.

**OpenGraph и Twitter Card.** Пакет `@moscowcss/og` рисует на сборке PNG-карточку каждой
индексируемой страницы: 1200×630 для OpenGraph и 1200×600 для Twitter, на языке страницы, в
цветах и шрифтах дизайн-системы. Базовый layout пишет полный набор мета-тегов: `description`,
`canonical`, `og:*` (включая тип, размеры и `alt` картинки, `og:locale`) и `twitter:*`
с `summary_large_image`.

**Адаптив по модели блога.** Значения шкалы описаны таблицами в дизайн-системе: база и
переопределения по брейкпоинтам, из таблиц генерируются CSS-переменные с медиазапросами.
Отступы внутри компонентов постоянны на всех ширинах; величины, которые по макету растут с
шириной, — отдельные layout-токены. Значения переводятся из `px` в `rem`. Корневой кегль —
`max(100%, 100vw / 120)`: до 1920px он равен настройке браузера, шире интерфейс растёт
пропорционально окну. Сами значения (цвета, размеры, отступы, скругления, кегли) остаются
нынешними: до 1920px сайт выглядит так же, как до изменения.

**Структура папок.** Как в блоге: `packages/{content,og,design-system,ui,icons,fonts,…}`,
`apps/website/src/{i18n,seo,content,layouts,pages,sections,…}`. Из корня репозитория убираются
мусор и дубли старой раскладки.

## Планка качества

- **«Сайт — одна страница митапа, значит SEO, i18n и проверки можно упростить».** Нет. Сайт
  перестаёт быть одностраничным в этой же спеке; мета-теги, `hreflang`, валидация контента и
  тесты делаются в полном объёме, как в блоге.
- **«В репозитории нет ни одного теста, значит и сейчас без них».** Отсутствие тестов — долг, а
  не норма. Логика, которую добавляет спека (валидация контента и связей, сверка переводов,
  выбор ближайшего митапа, резолвер шкалы, генератор карточек), покрывается vitest-тестами,
  `pnpm test` входит в CI.
- **«Контент будут править с телефона, значит схему надо сделать мягкой, все поля optional».**
  Нет. Мягкая схема пропускает пустую карточку на прод. Обязательные поля обязательны; удобство
  достигается короткими плоскими полями, длинным текстом в теле файла, заготовками и сообщением
  об ошибке, которое называет файл и поле.
- **«Значения токенов не меняем, значит и `@media` с литералами в компонентах можно оставить».**
  Нет. Значения сохраняются, но переезжают в таблицы дизайн-системы. В компоненте `@media`
  остаётся только для смены структуры (направление, колонки, видимость), размеры и отступы
  приходят токенами.
- **«Английская версия — заготовка, её можно не связывать и не проверять».** Нет. `en` проходит
  те же проверки схемы и инвариантов, что `ru`, и связан `hreflang`.
- **«У новых страниц нет макета, значит стили можно писать как получится».** Нет. Только
  компоненты `@moscowcss/ui` и токены; новый компонент заводится генератором `pnpm new:component`
  со стори.
- **«В блоге есть X, значит переносим и X».** Нет. Переносим ровно то, что перечислено в «Что
  делаем»; остальное в «Вне охвата».
- **«Визуал “вроде тот же”».** Сохранность внешнего вида проверяется сравнением скриншотов до и
  после (AC-21), а не на глаз.

## Вне охвата

- **CMS не подключаем:** контент правится файлами в git, этого достаточно для редакции из
  нескольких человек и для правки с телефона.
- **YML-файлы не заводим:** связи выражаются полями frontmatter и проверяются той же схемой, один
  формат проще для редакторов.
- **Третий язык не добавляем:** нужны два. Раскладка по папкам языков и так не требует правки кода
  под новый язык, отдельной абстракции под него не строим.
- **Значения токенов и внешний вид не меняем:** редизайн и новые значения — отдельная работа
  после макета; тёмная тема остаётся копией светлой.
- **RSS, `llms.txt`, Markdown-версии страниц, MCP-сервер, каталоги для агентов и JSON-LD из
  блога не переносим:** их нет в запросе, это отдельная SEO- и агентская работа со своими
  критериями.
- **Workshop-приложение блога не переносим:** демо компонентов в этом репозитории — Storybook, он
  остаётся.
- **Данные прошлых митапов (1–30) не набираем:** их нет в репозитории; спека даёт формат и
  команды, наполнение — работа редакции.
- **Тему-переключатель, страницы ошибок и 404 по образцу блога не делаем:** их нет в запросе.
- **Пересборку по расписанию не делаем:** сайт пересобирается каждым пушем контента, а новый
  митап редакция добавляет пушем же.
- **Push в `moscowcss-meetup/website`, настройку Pages и DNS делают люди:** это действия на
  чужой стороне, в спеке только workflow и инструкция.

## Критерии приёмки

### Структура

- **AC-1.** В корне репозитория нет файлов и папок старой раскладки: `src/`, `public/`,
  `scripts/`, `astro.config.mjs`, `tsconfig.json`, `gitignore`, `npmrc`; нет
  `apps/website/src/Новая папка/` и `apps/website/src/data/`. Проверка: `git ls-files` по этим
  путям пуст.
- **AC-2.** Есть пакеты `@moscowcss/content` (`packages/content`) и `@moscowcss/og`
  (`packages/og`), подключённые в `apps/website` через `workspace:*`; `apps/website/src` содержит
  папки `i18n`, `seo`, `content`, `layouts`. Каждый новый пакет имеет `CLAUDE.md` и `AGENTS.md`,
  побайтно одинаковые (`cmp` молчит), и корневой `CLAUDE.md`/`AGENTS.md` описывает новую раскладку.

### Контент

- **AC-3.** Коллекции страниц, митапов, докладов, спикеров, партнёров и FAQ объявлены в
  `@moscowcss/content`, файлы — только `.md`, по папкам `ru/` и `en/`. Весь текст, который сейчас
  лежит в `apps/website/src/data/*.ts` и в разметке `FAQSection`, перенесён в контент; русская
  главная показывает тот же текст, что до изменения.
- **AC-4.** Доклад, ссылающийся на несуществующего спикера или митап своего языка, роняет
  `pnpm build` с сообщением, в котором есть путь файла доклада и отсутствующее имя.
- **AC-5.** Перевод, у которого поле, не зависящее от языка (дата, время, митап, спикеры,
  ссылки), отличается от русской версии, роняет `pnpm build` с сообщением, где есть путь файла и
  имя поля.
- **AC-6.** Файл без обязательного поля роняет `pnpm build`; сообщение называет файл и поле.
- **AC-7.** Спикер с докладами на двух митапах (фикстура в тестах: митапы 10 и 15) получает на
  странице спикера оба доклада со ссылками на их митапы; митап на своей странице показывает
  доклады и перерывы одним расписанием по времени.
- **AC-8.** `pnpm new:event <номер>`, `new:talk <имя>`, `new:speaker <имя>`, `new:partner <имя>`,
  `new:faq <имя>` создают заготовки в `ru/` и `en/` из шаблонов пакета; при существующем файле
  команда ничего не создаёт и завершается с ненулевым кодом. Старые plop-генераторы
  `speaker/event/report` удалены.
- **AC-9.** README пакета `@moscowcss/content` описывает раскладку, поля каждой коллекции (что
  обязательно), связи, публикацию черновика и правку файла с телефона через веб-редактор GitHub.

### Языки и страницы

- **AC-10.** `/` отдаёт русскую главную с `<html lang="ru">`, `/en/` — английскую с
  `lang="en"`. На каждой странице переключатель языка ведёт на ту же страницу другого языка, а
  `<head>` содержит абсолютные `hreflang` на `ru`, `en` и `x-default`.
- **AC-11.** В `.astro`-файлах секций и страниц `apps/website` нет пользовательского текста
  литералами: строки приходят из словаря `src/i18n` или из контента.
- **AC-12.** Главная показывает ближайший будущий митап; если будущего нет — последний прошедший
  без кнопки регистрации и со ссылкой на запись, если она есть. Ниже — список прошлых митапов со
  ссылками на их страницы. Выбор «ближайшего» покрыт тестом с фиксированной датой.
- **AC-13.** Для каждого митапа, доклада и спикера в каждом языке есть страница
  `/events/<номер>/`, `/talks/<имя>/`, `/speakers/<имя>/` (с префиксом `/en/` для английского).
- **AC-15.** `pnpm build` строит индекс Pagefind; на `/search/` (и `/en/search/`) запрос по имени
  спикера или словам из названия доклада находит его страницу, и результаты относятся только к
  языку страницы. Страница поиска помечена `noindex`.

### OpenGraph и Twitter Card

- **AC-16.** Каждая индексируемая HTML-страница в `dist` содержит `description`, `canonical`,
  `og:title`, `og:description`, `og:type`, `og:url`, `og:locale`, `og:site_name`, `og:image`,
  `og:image:type`, `og:image:width`, `og:image:height`, `og:image:alt`, `twitter:card` со
  значением `summary_large_image`, `twitter:title`, `twitter:description`, `twitter:image`,
  `twitter:image:alt`. Проверку делает скрипт `check:seo`, он входит в CI и падает на первой
  нарушившей странице.
- **AC-17.** Файлы, на которые указывают `og:image` и `twitter:image`, существуют в `dist`, это
  PNG размером 1200×630 и 1200×600 соответственно (проверяет `check:seo`). Карточка показывает
  текст на языке страницы.

### Адаптив

- **AC-18.** Значения шкалы (кегли, отступы, layout-величины) описаны в дизайн-системе таблицами
  «база + переопределения по брейкпоинтам», CSS-переменные и медиазапросы `:root` генерируются из
  них; резолвер шкалы покрыт тестами.
- **AC-19.** В `.css.ts` файлах `packages/ui/src` и `apps/website/src` нет литералов в `px`, а
  внутри их `@media`-блоков нет литеральных размеров: свойства отступов, размеров и шрифта
  ссылаются на `vars.*`.
- **AC-20.** У `html` вычисленный `font-size` равен 16px при ширине окна 1920 и 32px при 3840
  (браузерные настройки по умолчанию).
- **AC-21.** Скриншоты каждой стори Storybook, существовавшей до изменений, и каждой нынешней секции
  русской главной (Hero, Program, Partner, FAQ, Join) на ширинах 375, 768, 1024, 1280 и 1920 совпадают
  с базовыми, снятыми с кода до изменений: доля отличающихся пикселей не больше 0,1 % на снимок. Шапка
  сайта (NavBar на главной) из сравнения исключена: AC-10 добавляет в неё переключатель языка; её стори
  без переключателя сравниваются как все. Hero сравнивается с базой с одной оговоркой: строка
  «Смотри трансляцию» без адреса трансляции — текст, а не пустая ссылка; остальной Hero совпадает с
  базой, дальше он сверяется точно со снимком после этого исправления (`.visual/hero-09`).

### Сборка

- **AC-22.** `pnpm lint`, `pnpm test`, `pnpm build`, `pnpm build:storybook` и `check:seo`
  проходят локально и в workflow деплоя; деплой выкладывает `dist` вместе с индексом Pagefind и
  карточками.
- **AC-23.** Workflow `.github/workflows/deploy.yml` рассчитан на репозиторий
  `moscowcss-meetup/website` и GitHub Pages через Actions: запускается на push в `master` и
  вручную, на pull request гоняет те же проверки без деплоя, версии pnpm и Node берёт из
  `packageManager` и `engines`/`.nvmrc`, а не из литералов в YAML. `site` в Astro — `https://css.moscow`.
  `docs/deploy.md` описывает разовую настройку на стороне GitHub и DNS: Pages → Source «GitHub
  Actions», custom domain `css.moscow`, записи A/AAAA апекса на адреса GitHub Pages.

## Открытые вопросы

- Перевод английской версии делает агент по текущему русскому тексту; вычитку перед публикацией
  делает редакция. На критерии не влияет.
- Имена спикеров латиницей в `en` даются транслитерацией, пока спикер не сообщит своё написание.
  На критерии не влияет.

## Решения

| Дата | Что изменено | Решение | Почему | Цена ошибки |
|---|---|---|---|---|
| 2026-11-03 | вне охвата | Только `.md`, без YML и CMS | Пользователь выбрал файлы в git; связи выражаются frontmatter-полями, один формат проще с телефона | Если редакторов станет много, понадобится CMS поверх тех же файлов — формат это допускает |
