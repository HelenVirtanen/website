How do we stop measuring a methodology by the number of dashes in class names and start seeing it as a way of thinking about project structure? Let us figure out (for the last time!) why modern React/Vue/Svelte developers need BEM, how it helps split an interface into components, reduce duplication and build a shared understanding between designer, markup developer and developer.
