title: "How to set up code that fixes itself?"
---

Sometimes you start work on a new project and the code looks as if different people wrote it. Working with such code gets harder.
In code review a lot of time goes into figuring out the property order and whether to put a trailing comma and a space or not.
Then, when you have your approvals and want to look at the git history, it is nothing but "fix".
In my talk I will show how to configure the code in a project so that it does not drift apart.
The benefits of using linters in a project and why they are needed.
